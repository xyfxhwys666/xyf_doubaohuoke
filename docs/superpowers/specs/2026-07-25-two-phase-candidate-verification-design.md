# 两阶段候选采集与真实性验证设计

## 目标

首次采集优先获得尽可能多的候选并立即展示，不自动执行真实性核验。用户可在任务完成后点击按钮，使用所选模型和公开网页证据执行真实性验证。

## 第一阶段：候选采集

- 公开网页结果和所选模型直接发现的候选合并保存。
- 候选必须包含公司名称以及用户要求的手机、邮箱或微信。
- 模型候选允许暂时没有公开来源 URL，但必须标记为“待验证”和“模型候选”，不得展示为真实已核验数据。
- 同一手机号、邮箱、微信或明显相同公司自动去重。
- 搜索源失败不阻止模型候选入库。

## 第二阶段：用户主动验证

- 任务结果页提供“开始真实性验证”按钮。
- 点击后使用任务所选模型分批核验现有候选，并检查已有来源网页。
- 验证只更新可信度、验证模型、验证详情和状态，不删除候选。
- 状态分为待验证、单模型符合、多模型一致、模型分歧、不符合或无法验证。

## API 与界面

- 新增 `POST /api/v1/collection-tasks/{task_id}/verify`。
- 任务增加验证执行状态，前端轮询期间显示进度。
- 下载和外部 API 原样包含验证状态字段。

## 约束

- 未验证候选不能标记为真实。
- 页面明确区分公开网页与模型候选。
- 模型验证失败时保留原候选并标记无法验证。
