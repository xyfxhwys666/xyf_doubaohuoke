# 中转站与豆包聊天网页混合采集设计

## 目标

定向恢复低成本采集通道：中转站模型负责批量发现候选公司，已登录的豆包聊天网页负责逐家查询联系方式。保留现有公司真实性筛选、手机号证据判定、最佳号码选择、持续任务、断点续跑和 ERP 全局去重。

## 通道分工

1. 中转站只用于解析自然语言、生成搜索词和批量发现候选公司。
2. 中转站返回的公司名不直接视为真实，仍需通过现有公开证据门禁。
3. 通过公司名门禁的候选，依次送入豆包聊天网页查询手机、邮箱、微信、地址和服务介绍。
4. 联系方式只有在公开来源中能与同一公司形成证据闭环时，才能自动有效或自动推送。
5. 模型或聊天页面只给出号码但无公开引用时，保留为待人工确认，不自动推送。

## 配置与切换

- 中转站使用独立的 `Base URL`、`API Key` 和模型名，不再依赖火山官方接入点。
- 豆包聊天网页继续使用 `data/doubao-browser-profile` 持久化登录状态。
- 页面仍由用户选择模型；选择豆包且网页已就绪时，任务走混合通道。
- 火山官方联网 API 不参与默认采集，也不作为聊天网页失败时的自动回退。

Codex 内置浏览器中已登录的豆包标签保留，用于当前人工验证。本地 FastAPI 服务无法持续接管 Codex 内置浏览器或迁移其登录信息；长时间自动任务必须使用应用独立的持久浏览器目录。

## 长时间运行

- 任务完成一轮后按原策略扩展同义词和新候选，直到达到严格有效目标或用户终止。
- 每家公司处理后保存检查点，应用重启后不重复已处理公司。
- 豆包登录失效、验证码、页面挑战或 DOM 改版时，任务自动暂停并显示原因；用户处理后点击继续。
- 单家公司查询超时或无联系方式时立即跳过，不阻塞队列。
- 聊天网页受登录和页面稳定性限制，可持续运行数天，但不承诺全程无人工干预。

## 去重与 ERP

保留当前持久化去重账本。同一手机号不得跨任务重复推送；同一公司只保留证据更强的手机号；更高证据质量的新号码沿用原 ERP GUID 更新。ERP 自动推送开关默认关闭。

## 验收标准

1. 候选发现请求发往中转站，不再调用火山官方 Responses API。
2. 联系方式逐家查询使用豆包聊天网页。
3. 网页掉线后任务暂停，重新登录并继续时不重复已处理公司。
4. 中转或聊天网页自述但无证据的手机号不自动有效。
5. 持续任务能暂停、继续、终止和跨重启续跑。
6. 不同任务发现相同公司或手机号时，ERP 不创建重复客户。
