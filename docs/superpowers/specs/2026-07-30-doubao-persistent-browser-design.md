# 豆包专用 Chrome 长期登录设计

## 目标

让采集系统长期复用同一个已登录豆包的 Chrome 会话，后端重启、任务暂停或连接中断时不关闭浏览器、不清理登录数据、不另开未登录窗口。

本设计不承诺绕过豆包登录过期、安全验证或网站风控。遇到这些情况时，系统暂停采集并等待用户在专用 Chrome 中处理。

## 方案

采用“用户拥有的专用 Chrome 进程 + 本机 CDP 连接”。

- 专用 Chrome 使用固定的独立用户目录，与日常浏览数据分离。
- Chrome 由用户启动或通过项目的“启动专用浏览器”操作启动，浏览器进程不属于后端任务。
- Chrome 仅在 `127.0.0.1` 暴露固定的 CDP 端口，不监听局域网或公网地址。
- 后端通过 Playwright `connect_over_cdp` 连接已有 Chrome，只管理豆包页面，不持有 Chrome 进程生命周期。
- 后端关闭时只断开 CDP 连接，不调用关闭 Chrome 或删除用户目录的操作。

## 组件

### 专用 Chrome 启动器

启动器负责定位 Chrome，使用项目固定的用户目录和 CDP 端口启动窗口，并打开豆包聊天页。启动前先检查端口；已有对应 Chrome 时直接复用，不重复启动。

用户目录中的 Cookie、Local Storage 和缓存由 Chrome 正常管理。项目不读取、导出或记录密码、Cookie 和会话令牌。

### CDP 连接适配器

现有 `PlaywrightDoubaoAdapter` 拆分为“连接模式”和现有的兼容模式。默认优先连接专用 Chrome：

1. 连接本机 CDP 端点。
2. 在已有页面中选择 `doubao.com/chat` 页面；不存在时新建一个豆包页面。
3. 执行输入框定位、提交提示词、等待回答和解析。
4. 连接丢失时不关闭 Chrome，以有界退避重连。

适配器的 `close()` 只释放 Playwright/CDP 客户端资源，不关闭浏览器、不关闭持久上下文。

### 状态与界面

后端对外提供以下状态：

- `browser_stopped`：专用 Chrome 未启动。
- `connecting`：正在连接或重连 CDP。
- `waiting_for_login`：Chrome 可用，但豆包需登录或安全验证。
- `ready`：已登录且可提交查询。
- `working`：正在查询公司或联系方式。
- `reconnecting`：连接中断，正在自动恢复。

前端展示连接状态，并提供“启动专用浏览器”和“重新连接”操作。任务因登录或连接问题暂停时，不清空候选队列、去重台账和已采集结果。

## 数据流

1. 用户启动专用 Chrome 并登录豆包。
2. 项目连接 CDP，校验豆包页面状态。
3. 持续任务按候选公司队列向豆包逐条查询联系方式。
4. 每条回答经格式解析、公司名称匹配、手机格式和证据检查后写入任务存储。
5. 前端轮询展示新增结果。
6. ERP 推送仍由任务的自动推送开关决定，本改造不自动改变开关。

## 异常处理

- Chrome 未启动：任务进入等待状态，页面提示启动专用 Chrome。
- CDP 断开：最多三次快速重连，之后进入低频重连；不重置任务进度。
- 豆包未登录或触发安全验证：暂停提交新查询，等用户处理后继续。
- 页面被用户关闭：在同一 Chrome 中新建豆包页，不启动新浏览器。
- Chrome 进程被用户关闭：任务保留进度并等待 Chrome 恢复，不循环弹出新窗口。
- 单家公司查询失败：记录失败原因并继续下一家，不阻塞整个队列。

## 安全边界

- CDP 仅监听 `127.0.0.1`。
- 使用独立用户目录，不连接用户日常 Chrome 配置。
- 后端日志不输出 Cookie、令牌、短信验证码或登录页表单值。
- 不自动处理滑块、验证码或其他安全挑战。
- 不自动对 ERP 扩大推送范围。

## 测试

- 单元测试：CDP 已连接、未启动、断开重连、页面重建和 `close()` 不关闭 Chrome。
- 状态测试：登录等待、安全验证、可用、工作中和重连状态的 API 映射。
- 任务测试：浏览器断开时保留队列和检查点，恢复后从未完成公司继续。
- 前端测试：连接状态、启动操作、重连操作和等待登录提示。
- 手工验收：登录一次后重启后端，确认 Chrome 窗口未关闭、豆包仍为登录状态、任务可继续且结果逐条出现。

## 验收标准

1. 用户只需在专用 Chrome 中登录一次。
2. 后端重启、任务暂停和任务结束都不关闭专用 Chrome。
3. 连接断开后可自动重连，不丢失已有结果和未完成队列。
4. 登录失效时明确显示等待登录，不循环新建浏览器。
5. 每条通过解析与核验的结果立即写入任务并出现在“采集结果”。
