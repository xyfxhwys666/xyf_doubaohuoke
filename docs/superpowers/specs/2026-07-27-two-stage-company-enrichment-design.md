# 两阶段公司候选与联系方式补全设计

## 目标

将现有“单次让模型同时返回公司和联系方式”的采集方式改为两阶段流程，提高候选公司数量，并降低公司名称与联系方式串配的概率。

用户仍只需输入自然语言需求并选择豆包、DeepSeek 或多个模型。系统自动解析城市、客户类型和所需联系方式。

## 核心规则

- 每个城市最多生成 100 家候选公司，多个客户类型关键词合并后去重，不是每个关键词各生成 100 家。
- 第一阶段只生成公司名称、命中关键词和候选理由，不要求联系方式。
- 第二阶段每次请求只询问一家公司，同时最多并行处理 3 家。
- 联系方式、地址、服务介绍或来源无法确认时必须返回 `null`，页面显示“未公开”。
- 不得把座机保存为手机号码。
- 每补全一家公司立即保存，页面无需等待整个城市完成即可显示结果。
- 模型生成的数据统一标记为“待验证”；没有公开来源或独立核验时不得显示为“已核验”。

## 数据流程

### 1. 自然语言解析

系统从用户输入中提取：

- 目标城市或全国城市范围；
- 客户类型关键词；
- 手机、邮箱、微信等联系方式要求；
- 数量限制；
- 用户在页面选择的模型。

未明确数量时，每个城市默认最多 100 家候选公司。

### 2. 候选公司生成

系统针对每个城市调用所选模型，要求只返回真实存在且符合需求的公司名称。模型返回结构：

```json
{
  "items": [
    {
      "company_name": "公司名称",
      "matched_keyword": "全案软装公司",
      "reason": "候选理由",
      "confidence": 70
    }
  ]
}
```

候选公司按标准化后的“城市 + 公司名称”去重。明显不是公司名称的标题、榜单、招聘信息和通用词不进入候选池。

候选池生成后立即保存并展示，状态为“待补全”。

### 3. 单公司信息补全

系统对候选池中的每家公司发起独立请求，一次请求只能包含一家公司。请求模型查找：

- 手机号码；
- 邮箱；
- 微信；
- 公司地址；
- 服务定位介绍；
- 公开来源链接；
- 字段置信度。

模型必须区分手机和座机。未知字段返回 `null`，不得根据号码格式、公司名称或常识补造信息。

系统允许同时处理 3 家公司，但每个模型请求仍只对应一家公司。每家公司完成后立即合并到任务数据并保存。

### 4. 多模型处理

- 只选择一个模型时，该模型负责候选生成和信息补全。
- 选择多个模型时，第一个模型生成候选池；其他模型补充候选并参与去重。
- 单家公司补全失败时，按用户选择顺序尝试下一个模型。
- 多模型对同一字段给出不同值时，不自动覆盖，保留冲突详情并标记“待验证”。
- 后续真实性验证仍由用户点击按钮触发，不在初始采集阶段自动执行。

## 任务进度

任务状态增加两个独立进度：

- 候选公司：已发现数量 / 100；
- 信息补全：已处理公司数 / 候选公司总数。

页面在第一家公司完成补全后立即显示数据，并持续刷新。某家公司补全失败不会阻塞同城市其他公司，也不会阻塞后续城市。

## 保存与去重

- 候选阶段使用“城市 + 标准化公司名称”去重。
- 补全阶段继续使用手机、邮箱或微信作为强唯一标识。
- 没有联系方式时保留公司候选，联系方式显示“未公开”。
- 后续发现同一家公司新的联系方式时更新原记录，不创建重复记录。
- 保存时间使用 `YYYY-MM-DD HH:mm:ss` 格式。

## 错误处理

- 候选生成失败：记录模型和城市错误，尝试下一个已选择模型。
- 单公司补全失败：最多重试一次，再切换下一个模型。
- 所有模型均失败：公司仍保留为“待补全”，任务继续。
- 模型返回无法解析的 JSON：记录错误，不保存不完整字段。
- 服务重启后：从已保存的候选和补全进度继续，避免重复询问已处理公司。

## 性能边界

每个城市最多 100 家候选，每家公司一次独立补全请求，默认并发数为 3。全国任务仍可能产生大量模型调用，因此必须按城市实时保存和展示，不能让用户等待整个全国任务完成后才看到结果。

## 测试要求

- 模型候选响应只能包含公司名称等候选字段。
- 每次补全请求只包含一家公司。
- 100 家候选可以逐家补全并实时保存。
- 无联系方式的公司仍被保留并显示“未公开”。
- 座机不会进入手机字段。
- 公司名称按城市去重。
- 单模型失败后可以切换到下一个已选择模型。
- 重启后不会重复补全已经处理的公司。
- 页面能分别显示候选生成和信息补全进度。

## 不在本次范围

- 不保证模型记忆中的公司或联系方式绝对真实。
- 不自动将模型候选标记为“已核验”。
- 不接入新的外部企业数据库或付费工商数据源。
- 不调整登录、权限、计费或多租户体系。
