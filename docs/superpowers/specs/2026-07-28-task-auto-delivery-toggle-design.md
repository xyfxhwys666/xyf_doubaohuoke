# 多任务采集控制与 ERP 自动推送设计

## 目标

用户创建采集任务时自行决定是否自动推送 ERP。开关默认关闭。无论是否推送，发现的公司都必须先保存并展示在采集结果中；开启后再将具备有效联系方式的公司逐条推送，并在每一行展示推送状态。

系统同时保留和展示多个采集任务。任务采用受控并行方式运行，默认最多同时运行两个任务，超出的任务自动排队。每个任务可以独立暂停、继续和终止，新建任务不会替换或隐藏旧任务。

## 用户流程

1. 用户输入自然语言需求并选择模型。
2. 用户选择是否开启“自动推送 ERP”，默认关闭。
3. 用户点击“创建并开始采集”。
4. 每发现一家公司，系统先写入任务 JSON，采集结果立即出现该公司。
5. 豆包完成单家公司联系方式补全后：
   - 开关关闭：该行显示“仅展示”，不调用 ERP。
   - 开关开启且至少有手机、邮箱或微信之一：该行依次显示“待推送”“推送中”“推送成功”或“推送失败”。
6. ERP 单条失败不影响后续公司继续采集。
7. 用户可以在任务列表中切换查看不同任务，并独立控制每个任务。

## 多任务调度

- 默认最多同时运行两个采集任务，避免豆包、DeepSeek 等模型接口集中限流或瞬时费用过高。
- 并发上限由后端配置控制，初始值为 `2`，前端不向普通用户提供修改入口。
- 达到并发上限后，新任务进入 `queued` 状态；任一运行任务完成、暂停或终止后，队列中最早创建的任务自动开始。
- 新建任务不会替换、删除或终止已有任务。
- 不同任务的自然语言需求、模型选择、结果、进度、错误和 ERP 推送状态完全隔离。
- 单个任务内部继续限制模型请求和 ERP 请求的并发；ERP 推送始终逐条串行执行。

## 任务状态与控制

任务状态包括：

- `queued`：等待可用执行名额。
- `running`：正在采集或补全联系方式。
- `pausing`：已收到暂停指令，等待当前请求安全结束。
- `paused`：已暂停，不再发起新的模型或 ERP 请求。
- `completed`：任务正常完成。
- `completed_with_errors`：任务完成，但部分城市、公司或推送步骤失败。
- `terminating`：已收到终止指令，等待当前请求安全结束。
- `terminated`：任务已终止，已有结果保留。

控制规则：

- “暂停”只对 `running` 任务可用。当前已经发出的单次模型或 ERP 请求允许结束，随后保存结果并进入 `paused`，避免产生半条数据。
- “继续”只对 `paused` 任务可用。任务重新进入调度队列；有空闲名额时从已保存的城市、关键词、候选公司和补全进度继续，不重复已完成步骤。
- “终止”对 `queued`、`running`、`pausing` 和 `paused` 任务可用。运行中的请求安全结束后进入 `terminated`。
- 终止不会删除已采集线索、推送状态、日志或下载能力；已终止任务不可继续，如需重跑则创建新任务。
- 暂停或终止一个任务不影响其他任务。

## 数据模型

任务增加字段：

- `auto_deliver: bool`：是否为该任务自动推送，默认 `false`，创建后固定随任务保存。
- `status`：任务当前调度状态。
- `pause_requested: bool`：是否请求在当前安全检查点后暂停。
- `terminate_requested: bool`：是否请求在当前安全检查点后终止。
- `checkpoint`：已完成的城市、关键词、候选发现和联系方式补全位置，用于继续执行。
- `created_at`、`started_at`、`paused_at`、`terminated_at` 和 `completed_at`：任务生命周期时间。

线索增加字段：

- `delivery_status`：`display_only`、`pending`、`sending`、`succeeded` 或 `failed`。
- `delivery_error`：推送失败原因；其他状态为空。
- `delivered_at`：ERP 成功接收时间；未成功时为空。

旧任务缺少这些字段时按 `auto_deliver=false` 和 `delivery_status=display_only` 处理，避免升级后自动推送历史数据。

## 后端流程

- 自然语言创建任务接口接收 `auto_deliver`，默认 `false`。
- 系统级 `ERP_AUTO_PUSH` 仍作为总开关；只有系统已配置且任务 `auto_deliver=true` 时才推送。
- 候选公司从模型返回后逐条保存，并同步更新 `candidate_count`，使页面轮询能逐步显示结果。
- 联系方式补全后先保存线索，再将状态写为 `pending` 和 `sending`，随后调用 ERP。
- ERP 返回 `errCode == 0` 时写为 `succeeded`；网络错误、HTTP 错误、无效响应或业务错误写为 `failed` 并保存错误信息。
- ERP 请求保持串行发送，确保一家公司一家公司推送；候选发现和联系方式补全仍可保留现有并发能力。
- 成功指纹和失败队列继续用于幂等与重试。
- 调度器维护运行任务集合和先进先出等待队列，默认只向两个任务授予运行名额。
- 采集服务在城市切换、关键词切换、候选公司保存、联系方式补全和 ERP 推送前后检查暂停及终止标记。
- 每个检查点先持久化进度，再释放运行名额，确保进程重启或页面刷新后可以恢复。
- 后端启动时将异常中断的 `running`、`pausing` 和 `terminating` 任务恢复为可判断状态：终止请求进入 `terminated`，暂停请求进入 `paused`，其余任务重新进入队列。

## 前端界面

- 在模型选择区域下方新增开关“自动推送 ERP”，默认关闭。
- 开关旁显示当前含义：关闭为“只保存并展示”，开启为“有效线索逐条推送”。
- ERP 系统未配置时开关禁用，并显示“ERP 未配置”。
- 采集结果表新增“ERP 推送”列，显示：
  - 仅展示
  - 待推送
  - 推送中
  - 推送成功
  - 推送失败
- 推送失败时在状态旁提供失败原因提示，不把密钥或鉴权信息展示到页面。
- 原“批量推送到其他 API”功能保留，并明确标记为手动推送到其他系统，避免与固定 ERP 自动推送混淆。
- 页面新增任务列表，展示任务名称或需求摘要、创建时间、所选模型、状态、城市进度、候选数、有效联系方式数和 ERP 推送统计。
- 用户点击任务列表中的任务后，右侧或下方展示该任务的执行进度与采集结果；切换任务不会停止后台采集。
- 每个任务根据状态显示可用的“暂停”“继续”“终止”按钮；不可用操作置灰，操作提交期间禁止重复点击。
- 排队任务显示排队状态；开始运行后自动刷新为采集中。
- 旧任务继续保留在列表中，不因创建新任务而消失。

## 接口

- `GET /api/v1/delivery-config`：返回 `{ "configured": true | false }`，供前端决定开关是否可用。
- `POST /api/v1/collection-tasks/from-natural-language`：请求增加 `auto_deliver`。
- 任务与线索查询响应包含新增状态字段。
- `GET /api/v1/collection-tasks`：返回当前账号可见的任务列表和摘要统计。
- `POST /api/v1/collection-tasks/{task_id}/pause`：请求暂停任务。
- `POST /api/v1/collection-tasks/{task_id}/resume`：将已暂停任务重新加入调度队列。
- `POST /api/v1/collection-tasks/{task_id}/terminate`：请求终止任务。
- 控制接口必须校验任务归属和当前状态；重复请求返回当前任务状态，不重复执行副作用。

## 异常处理

- 关闭开关时绝不调用 ERP，也不创建失败记录。
- 开启但 ERP 未配置时，创建任务返回明确校验错误，不静默降级。
- 没有有效联系方式的公司保留在结果中，状态显示“仅展示”，不推送。
- 推送失败后保留公司数据和失败原因，采集任务继续执行。
- 页面刷新后从任务 JSON 恢复开关和逐条推送状态。
- 模型限流、超时或临时网络失败只记录到对应任务，采用现有重试规则，不阻塞其他任务。
- 调度器自身异常不得把同一任务启动两次；任务获得运行名额和释放名额都必须在进程内原子完成。
- 暂停、继续和终止请求在任务已经完成后返回明确的状态冲突，不修改历史结果。

## 验收标准

- 新任务默认关闭自动推送。
- 关闭时，公司会逐步出现在结果表中且没有 ERP 请求。
- 开启时，公司先出现，再按单条顺序进入推送流程。
- 每一行能显示并持久化推送中、成功和失败状态。
- ERP 失败不会中断后续公司采集。
- 旧任务不会因为升级自动推送。
- 下载、真实性验证、采集失败重试和手动 API 推送功能保持可用。
- 页面能够同时展示多个新旧任务，并可切换查看各自结果。
- 默认最多两个任务同时运行，第三个及后续任务按创建顺序排队。
- 新建任务不会替换、隐藏、暂停或终止旧任务。
- 运行任务可以暂停；暂停后不再发起新请求，继续后从持久化检查点执行。
- 排队、运行或暂停任务可以终止；终止后已有数据仍可查看和下载。
- 一个任务暂停、终止、失败或 ERP 推送失败不影响其他任务。
- 页面刷新和后端重启后，任务列表、控制状态和执行进度保持一致。
