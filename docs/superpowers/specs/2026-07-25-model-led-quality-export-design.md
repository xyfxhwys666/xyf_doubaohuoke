# 模型主导采集与数据质量设计

## 目标

以大模型理解任务、判断客户匹配和整理服务定位，公开网页负责提供企业及联系方式证据，高德作为用户可选的真实性兜底。正式结果不包含模型生成但没有来源证据的企业或联系方式。

## 采集流程

1. 用户选择城市、关键词、至少一个可用模型、需要具备的联系方式以及是否启用高德。
2. 公开网页按城市和关键词发现企业证据；高德启用时并行补充标准企业名称、地址和手机。
3. 模型基于来源 URL、企业名、地址、服务介绍和联系方式判断是否符合任务。
4. 仅保留所有选中模型均判断符合、所有必选联系方式均存在、且有来源 URL 的记录。
5. 去重时合并来源字段，优先保留高德标准名称，网页证据补充邮箱和微信。

## 联系方式规则

- 用户可勾选手机、邮箱、微信中的一项或多项。
- 所有勾选项必须同时存在，记录才能进入正式结果。
- 未勾选或来源中未找到的字段在页面和导出中显示“未公开”。
- 座机不算手机联系方式。

## 模型与高德

- 至少选择一个已配置模型。
- DeepSeek、豆包、通义千问、Kimi、OpenAI、Claude、Gemini 均展示在页面。
- 未配置模型置灰，后续配置 API 后可启用。
- 高德是可选真实性兜底，不是模型调用的前置条件。
- 模型不得新增证据中不存在的企业、手机、邮箱或微信。

## 数据质量

- 被任一模型判定不符合、模型调用失败或多模型结论有分歧的记录不进入正式结果。
- 搜索来源使用限速、重试和退避，错误需要在任务状态中显示，不能把部分失败伪装成全国完成。
- 网页搜索标题只作为候选名称；高德存在时优先使用高德名称，网页结果需要清除“电话”“联系我们”等标题噪音。

## 下载

- 用户在页面选择 XLSX、CSV 或 JSON 后下载。
- 全国任务按城市打包 ZIP，只包含有正式结果的城市，不生成空城市文件。
- 所有格式字段一致，空值写“未公开”。

## 验证

- 后端测试覆盖联系方式全满足、模型过滤、名称清理、空城市不导出及三种格式。
- 前端通过类型检查与生产构建。
- 使用少量真实城市完成网页证据、模型判断、高德可选和下载闭环。
