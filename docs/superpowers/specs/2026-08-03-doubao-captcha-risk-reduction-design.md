# 豆包网页验证码触发风险降低设计

## 目标

在不绕过验证码、登录限制或豆包风控的前提下，降低豆包网页采集触发安全验证的频率，并将人工干预缩减为只在验证码实际出现时完成验证。验证完成后由系统自动检测页面恢复并从任务断点继续。

无法保证验证码永不出现。豆包的触发规则属于第三方动态风控，系统只能通过更保守的请求节奏、单账号串行使用和稳定浏览器会话降低概率。

## 方案比较

### 方案 A：保持现状

- 查询间隔随机 8～15 秒。
- 连续 40 次后休息 10～20 分钟。
- 优点是速度较快且无需修改。
- 缺点是长时间运行仍可能集中触发风控，且后台允许多个任务争用同一豆包账号。

### 方案 B：保守节流与自动恢复（采用）

- 查询间隔随机 15～30 秒。
- 连续 20～25 次后休息 20～30 分钟。
- 同一豆包浏览器账号同时只允许一个网页采集任务占用。
- 检测到验证码后立即停止发送新请求，不自动重试、不自动点击验证码。
- 后台低频检查页面状态；用户完成验证码后，任务自动从已保存的公司断点恢复，无需再次点击“继续”。
- 优点是对现有网页聊天方案改动小，最有利于降低验证码频率和人工操作次数。
- 缺点是吞吐降低，且仍无法承诺永不出现验证码。

### 方案 C：官方 API 或混合采集

- 候选发现和公开网页核验使用官方 API 或合规数据接口，豆包网页只补充少量难查联系方式。
- 优点是最稳定、验证码最少。
- 缺点是可能产生接口费用，且当前用户要求继续使用已登录豆包网页，因此本次不采用。

## 运行规则

### 请求节奏

- 默认最小间隔：15 秒。
- 默认最大间隔：30 秒。
- 每批请求数：在 20～25 之间随机选择；同一批次内不重置计数。
- 批次冷却：在 1200～1800 秒之间随机选择。
- 后端重启后不通过重置计数立即突发请求；持久化最近一次请求时间、当前批次计数和冷却截止时间。

### 单账号串行

- 豆包网页网关增加任务所有权。
- 第一个进入豆包网页阶段的任务取得账号租约。
- 其他网页任务保持排队状态，不向豆包页面发送提示词。
- 当前任务暂停、终止或完成时释放租约，让下一个任务运行。
- 当前任务进入验证码等待状态时保留账号租约，避免其他任务继续撞击同一验证页面；页面恢复后仍由原任务优先续跑。
- 公开网页搜索和不使用豆包网页的任务不受该租约影响。

### 验证码处理

- 页面出现“安全验证”等挑战标识后，任务进入 `waiting_for_login`，保存当前城市、公司索引和已处理公司名称。
- 网关停止接收该账号的新提示词，并记录挑战首次出现时间。
- 后台每 60 秒执行一次只读页面状态检查，不提交消息、不刷新页面、不重建浏览器配置。
- 连续两次检测到页面恢复为 `ready` 后，自动将原任务重新排队并从当前公司继续。
- 验证码未处理时不重复恢复任务，避免循环触发和日志刷屏。

### 浏览器会话

- 始终复用现有持久化 Chrome 用户目录和 CDP 端口。
- 后端重启只重新连接现有浏览器，不创建新的浏览器配置。
- 自动恢复不重新登录、不清理 Cookie、不打开额外豆包标签页。

## 状态与界面

- 浏览器状态增加：`cooldown`、`waiting_for_login`、`ready`。
- 任务卡片在冷却时显示预计恢复时间。
- 验证码出现时显示“等待人工完成豆包验证，完成后将自动续跑”。
- 自动恢复成功后记录一次活动日志，避免用户误以为任务仍停着。

## 数据安全与断点

- 每次豆包响应解析完成后立即保存采集结果。
- 当前公司请求前保存公司索引；成功处理后再推进索引。
- 验证码、后端重启或浏览器断线不清空候选、联系方式、ERP 状态和去重台账。
- 已推送 ERP 的线索继续按公司、手机号、邮箱和指纹去重。

## 验收标准

1. 两个豆包网页任务同时启动时，只有一个任务能够发送提示词，第二个保持排队。
2. 连续请求间隔始终处于 15～30 秒，批次大小处于 20～25，批次冷却处于 20～30 分钟。
3. 检测到验证码后没有任何自动提交、自动点击或短时间重复请求。
4. 人工完成验证码后，系统在不超过 120 秒内自动恢复原任务，并从未完成公司继续。
5. 后端重启后仍复用原 Chrome 配置，并保留节流状态和任务断点。
6. 现有采集结果、人工 ERP 推送、跨任务去重和任务暂停/终止行为不回归。

## 非目标

- 不识别、破解或自动点击验证码。
- 不伪造鼠标轨迹、浏览器指纹或账号行为。
- 不保证第三方豆包网页永不触发验证码。
- 不启用新的付费联网搜索 API。

## 实现记录

- 生产节奏默认为每条提示词随机间隔 15～30 秒，每批随机 20～25 条，批次之间随机冷却 20～30 分钟。
- 节奏状态保存在数据目录的 `doubao-web-pacing.json`，后端重启后继续遵守上次记录的间隔或冷却时间。
- 同一豆包账号由任务租约限制为单任务使用；进入人工验证等待的任务保留租约，终止或完成后释放。
- 后台每 60 秒只读检查一次页面状态，连续两次为 `ready` 后从任务断点自动续跑。
- 实现不识别、不点击、不绕过验证码，也不创建新的 Chrome 用户目录或额外豆包标签页。
