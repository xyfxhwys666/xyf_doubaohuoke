# 联系方式公开证据门槛设计

## 目标

在已有“公司名称公开证据核验”之后，增加联系方式证据门槛。豆包仍逐家联网查询，但其回答只是待核对候选；后端必须重新访问来源页面，确认公司全称和手机号同时存在，才标记为“公开网页已核验”。

系统不宣称可以绝对证明外部网页内容的真实性，但必须保证：没有可重新访问和复查的证据，就不标记为真实、不自动推送 ERP，也不使用模型推测的姓名、职务或联系方式。

## 固定流程

1. 用户选择模型并用自然语言提交城市、客户类型、数量和联系方式要求。
2. 候选发现模型生成公司名单。
3. 底层公开网页搜索核验完整公司名称、城市和目标业务。
4. 只有公司名称证据通过后，才调用豆包逐家查询手机号、联系人姓名、职务和来源。
5. 豆包必须返回结构化候选：公司全称、手机号、联系人、职务、来源 URL、页面标题和证据原文。找不到时必须返回空值。
6. 后端重新请求来源 URL，从可见正文中校验公司全称和手机号。
7. 通过后才保存为已验证联系方式；失败时保留公司候选，但手机号不进入已验证结果。
8. ERP 只自动推送公司名称和手机号都通过证据门槛的数据。

## 公司名称规则

公司名称继续使用现有状态：`verified_public_web`、`verified_registry`、`unverified`、`rejected` 和 `verification_failed`。

`verified_public_web` 必须满足以下任一条件：

- 一个可访问页面正文同时包含完整公司名称、目标城市和业务关键词；
- 两个不同域名的页面正文都包含完整公司名称，合并证据能确认目标城市和业务。

搜索结果标题、模型回答、不可访问页面、类似名称、简称或不同城市公司都不能通过。

## 联系方式证据规则

联系方式验证状态为：

- `verified_public_web`：来源页面正文同时包含完整公司名称和相同手机号。
- `unverified`：豆包返回了数据，但来源无法完成同页复核。
- `rejected`：页面不包含该公司全称、手机号不一致、只有座机或页面明确指向其他公司。
- `verification_failed`：页面请求超时或解析异常，可稍后重试，但不得先行推送。

手机号必须符合中国大陆 11 位格式，不接受座机、脱敏号码、推测号码或只存在于模型回答中的号码。

联系人姓名和职务只在来源页面原文明确出现时保存。没有证据时显示“未公开”，不从微信昵称、公司名、手机号归属地或职位常识推断。

## 数据字段

线索增加：

- `contact_person_name`
- `contact_person_role`
- `contact_verification_status`
- `contact_evidence_url`
- `contact_evidence_quote`
- `contact_verified_at`
- `contact_verification_reason`

旧数据缺少上述字段时按 `unverified` 处理，不影响历史展示，也不重复推送已成功的 ERP 记录。

## 豆包输出约束

逐家补全提示词必须明确：

- 只提取联网检索结果中明确公开的数据；
- 不得补全、推测、组合或修改号码；
- 来源 URL 和证据原文为必填项；
- 找不到同页证据时返回 `NOT_FOUND`；
- 一次只查询一家已通过名称核验的公司。

后端不把“模型按要求返回了 JSON”当作真实性证明。

## 前端和导出

结果表新增：

- 联系人
- 职务
- 手机证据状态
- 联系方式证据链接

导出 XLSX、CSV 和 JSON 同步包含这些字段。无证据字段统一显示“未公开”或“未验证”。

## ERP 推送门槛

自动推送必须同时满足：

```text
company_name_verification_status in {verified_public_web, verified_registry}
AND contact_verification_status == verified_public_web
AND mobile is valid
AND contact_evidence_url is HTTP(S)
AND verification_status in {single_model_match, model_consensus_match}
```

联系人姓名和职务不作为推送必填项，因为大量公司只公开业务手机号。ERP 接收协议已支持时才映射联系人和职务，否则仅保存于本地线索和导出文件。

## 失败、重试和并发

- 公司名称核验和联系方式核验分开记录状态和原因。
- 网络异常使用有限重试，业务证据不足不重试为成功。
- 同一任务内按“城市 + 规范化公司名 + 手机号”复用核验结果。
- 任务暂停、终止和后端重启时保留已核验进度，不重复请求已通过页面。

## 测试与验收

- 豆包返回手机号但来源页面无该号码时，必须拒绝。
- 来源页面有手机号但无完整公司名称时，必须拒绝。
- 只有座机、脱敏号码或不同公司手机号时，必须拒绝。
- 来源正文同时包含完整公司名称和相同手机号时，标记为已验证。
- 联系人和职务只有原文证据时保存，无证据时留空。
- 名称或手机证据未通过的数据不得自动推送 ERP。
- 前端、三种导出格式和 API 返回结构能区分“模型候选”与“公开网页已验证”。
- 原有模型选择、任务队列、暂停、终止、导出和 ERP 幂等行为不回归。
