# 公司名称公开证据前置核验设计

## 目标

在“模型发现候选公司”和“豆包逐家公司查询联系方式”之间增加公司名称证据门槛，减少模型虚构公司名后继续消耗豆包请求并产生错误联系方式的问题。

本阶段只核验公司名称、所在城市和主营方向是否有公开网页证据，不声明工商登记真实性。企查查只通过官方 API 接入；未提供 API 授权前不调用，也不抓取企查查网页。

## 固定采集顺序

1. 用户自然语言说明城市、客户类型和联系方式要求。
2. 用户在现有模型区域选择发现与核验模型。
3. 所选模型给出候选公司名称。
4. 底层公开网页搜索按“城市 + 完整公司名称”检索证据。
5. 只有公司名称证据通过的候选，才逐家公司调用豆包联网查询联系方式、地址和服务介绍。
6. 联系方式补全后继续执行现有模型真实性核验。
7. 只有同时满足手机号、公开来源、公司名证据通过和模型核验通过的数据，才允许自动推送 ERP。

豆包联系方式补全保持现有逻辑，不回退到 DeepSeek 或其他模型。

## 公司名称证据规则

候选公司名先经过现有规范化逻辑，必须是可识别的企业全称，不能只是品牌词、文章标题、服务中心、联系电话标题或营销描述。

公开网页核验结果分为：

- `verified_public_web`：公开网页证据通过。
- `verified_registry`：未来通过企查查官方 API 核验工商全称和存续状态。
- `unverified`：证据不足，保留本地但不进入豆包补全。
- `rejected`：网页证据明确指向不同公司、不同城市或不相关主营方向。
- `verification_failed`：公开搜索超时或异常，保留本地并记录错误。

`verified_public_web` 必须满足以下任一条件：

- 一个可访问的公开页面同时包含规范化完整公司名称、目标城市信息，以及至少一个用户目标关键词或其核心业务词；
- 两个不同域名的公开页面都包含规范化完整公司名称，并且合并证据能够确认目标城市和主营方向。

以下情况不得通过：

- 只有模型回答，没有 HTTP(S) 来源链接；
- 网页只出现简称或相似名称，未出现完整公司名称；
- 搜索结果标题是“十大公司”“联系方式”“招聘”“黄页列表”等聚合标题，但正文不能确认该企业；
- 名称存在但城市不一致；
- 名称存在但主营方向与用户需求无关；
- 来源页面无法访问，且搜索摘要也没有足够的完整名称、城市和业务证据。

## 数据字段

候选线索增加：

- `company_name_verification_status`
- `company_name_evidence_urls: list[str]`
- `company_name_verification_reason`
- `company_name_verified_at`
- `company_name_verification_attempts`

旧线索缺少这些字段时按 `unverified` 处理，但不会自动重新推送 ERP。已经成功推送的历史 ERP GUID 保持成功状态，不因升级重复发送。

## 后端组件

在公开网页提供器增加只读方法：

```python
verify_company_name(
    *,
    company_name: str,
    city: str,
    keywords: list[str],
) -> CompanyNameEvidence
```

该方法使用现有搜索客户端、重试、限速、HTML 解析和来源 URL 处理，不查联系方式，也不修改候选名称。它返回核验状态、证据 URL、理由和命中的城市/业务信号。

采集服务在候选持久化后、豆包补全前执行名称核验。名称核验逐条持久化，任务暂停、终止或后端重启时从未核验候选继续。单家公司核验失败不终止其他公司。

为控制搜索压力，公司名称核验最多三个并发请求；同一任务内按规范化公司名和城市缓存结果，持续轮次遇到相同候选时复用证据，不重复搜索。

## ERP 安全门槛

验证后自动推送新增公司名称条件：

```text
company_name_verification_status in {verified_public_web, verified_registry}
AND mobile is valid
AND source_url is HTTP(S)
AND verification_status in {single_model_match, model_consensus_match}
```

任何字段缺失都默认不推送。手动下载仍包含未通过候选及原因，方便人工复核。

## 前端展示

不新增创建任务开关，公司名称公开证据核验是防止虚假数据的固定底层步骤。

执行进度增加“公司名称核验”阶段和已通过/未通过数量。结果表增加“公司名称核验”列，显示“公开网页已核验”“工商已核验”“证据不足”“不符合”或“核验失败”，并可通过来源链接查看证据。

现有模型选择区、持续采集开关、验证后自动推送开关和豆包联系方式补全流程不变。

## 企查查边界

预留 `CompanyRegistryVerifier` 接口和配置字段，但本阶段不实现网页抓取。获得企查查官方 API 的请求地址、授权方式、应用凭证和字段文档后，再增加 `verified_registry` 实现。密钥只保存在 `.env`，不进入前端、日志或 Git。

## 验收标准

- 模型虚构且公开网页找不到完整名称的候选不会调用豆包。
- 相似公司名、简称和聚合文章标题不能冒充完整企业名称。
- 公开证据同时确认完整名称、城市和主营方向时才进入豆包补全。
- 名称核验状态和证据逐条持久化并展示。
- 暂停、继续、终止、持续轮次和后端重启不会重复核验已缓存公司。
- 名称未通过的线索绝不自动推送 ERP。
- 原有豆包补全、模型选择、下载、任务隔离和 ERP 幂等行为不回归。
