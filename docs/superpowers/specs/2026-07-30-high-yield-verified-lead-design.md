# 高产出真实客户信息采集设计

## 目标

系统持续、自动地寻找大量真实公司，并只将能够证明“完整公司主体与中国大陆手机号真实对应”的记录标记为有效。地址、服务介绍、联系人姓名和职务尽量补充，但不是有效性的必要条件。

系统不承诺所有公司都有公开手机号，也不使用模型自述代替证据。提高产出的方式是扩大候选池、增加搜索路径和允许可靠的跨来源证据闭环，而不是降低真实性要求。

## 核心原则

1. 公司名称必须是完整主体或可解析到完整主体的明确品牌，行业泛称不得直接成为有效公司名。
2. 有效记录必须包含符合规则的 11 位中国大陆手机号。
3. 豆包联网搜索负责候选发现、公司主体确认、联系方式搜索和手机号反向确认。
4. 模型输出没有公开引用时不得自动通过。
5. 同一公司只保留证据最强的一条手机号记录。
6. ERP 推送前执行全局去重，后续任务和后续轮次不得重复创建同一客户。

## 证据分级

### A 级：权威单来源自动有效

以下来源直接同时出现完整公司主体和手机号时，一个来源即可通过：

- 企业官网或官方账号公开页面
- 企业年报、政府公示或交易所披露
- 可识别企业主体的工商信息页面
- 行业协会或其他明确权威来源

### B 级：双来源闭环自动有效

普通网页不要求完整工商名称和手机号必须出现在同一页面，但必须形成闭环：

1. 来源一证明完整公司主体真实存在，并确认所在城市或主营方向。
2. 来源二显示该公司的品牌、简称或完整名称与手机号的关系。
3. 系统能够证明品牌或简称属于该完整公司主体。
4. 使用手机号反向搜索时，结果回到同一主体、品牌或明确关联页面。

四项满足后标记为自动有效。两个来源不能只是相互转载的同一篇内容。

### C 级：待人工确认

手机号通过微信或其他人工方式可以确认，但自动搜索没有足够公开引用时，记录进入待人工确认区。用户可点击“人工确认并推送”，系统保存操作账号、时间和备注。人工确认前不得自动推送。

### 无效

以下情况不得计入有效数据：

- 只有模型回答，没有可访问的公开来源
- 公司名称是“室内设计公司”等行业泛称且无法修正为完整主体
- 手机号反向搜索到其他无关公司
- 号码是座机、虚拟占位符或格式不合法
- 证据内容与公司主体冲突

## 自动采集漏斗

### 1. 扩大候选池

系统默认每获得 1 条有效记录，允许扩展最多 20 家候选。候选不足时继续运行，不把候选数量当成任务完成条件。

搜索按城市行政区、业务类型和同义词展开，例如：别墅设计、私宅设计、大宅设计、全案落地、软装陈设、整装设计等。每轮排除已经处理的公司和查询组合。

### 2. 主体标准化

候选先解析为完整公司主体。若搜索结果给出行业泛称，但摘要中包含完整公司名，系统使用有证据的完整名称替换泛称。品牌名与工商主体建立别名关系，后续统一使用标准主体键。

### 3. 三阶段联系方式搜索

对每个通过主体确认的公司依次执行：

1. 使用完整公司名搜索手机号和联系方式。
2. 使用品牌名、简称及业务关键词搜索手机号。
3. 对发现的手机号执行反向搜索，验证其归属。

每家公司限制单轮查询次数。当前公司无法闭环时立即进入下一家公司，后续可使用不同查询词或来源重试，不能阻塞整个任务。

### 4. 最佳号码选择

同一公司有多个真实手机号时，根据以下顺序选择一条：

1. 来源权威性
2. 正向与反向证据一致性
3. 独立来源数量
4. 是否包含联系人姓名和职务
5. 证据更新时间

低分号码保留为候选证据，但不生成第二条 ERP 客户记录。

## 全局去重与更新

系统维护轻量的持久化去重账本，不作为完整客户数据库：

- `normalized_mobile`：手机号第一唯一键
- `canonical_company_key`：标准化公司主体第二唯一键
- `company_aliases`：品牌、简称和工商全称映射
- `erp_customer_guid`：同一主体稳定使用同一个 ERP GUID
- `evidence_score`：当前已推送号码的证据质量
- `delivered_at`：最近成功推送时间

处理规则：

1. 手机号已经成功推送时，后续任何任务直接标记为重复跳过。
2. 公司主体已经推送且新记录质量不高于旧记录时，跳过推送。
3. 同一公司发现更高质量的新手机号时，使用原 ERP GUID 更新现有客户，不创建重复客户。
4. 推送请求保持幂等；网络重试不能产生第二条客户记录。
5. 本地任务历史删除或应用重启后，去重账本仍然有效。

## 页面行为

采集结果增加以下状态：

- 自动有效
- 待人工确认
- 人工已确认
- 已推送
- 重复跳过
- 证据冲突

待人工确认记录提供“人工确认并推送”按钮。点击前展示公司名称、手机号、现有来源和风险提示；点击后保存审计信息并按全局去重规则推送。

## 失败与降级

- 豆包联网请求超时或限流时按指数退避重试，不丢失任务进度。
- 单家公司连续失败后暂时跳过，继续处理候选队列。
- 搜索来源进入登录页、无关聚合页或明显垃圾页面时加入来源黑名单。
- 已成功解析的公司别名和证据结果缓存，避免重复消耗联网额度。
- ERP 不可用时保留待推送状态，恢复后按幂等键重试。

## 验收标准

1. A 级和 B 级记录能够展示公司与手机号的证据闭环。
2. 模型自述但无公开证据的手机号不会自动有效或自动推送。
3. 泛称候选能修正为完整主体，无法修正时保持无效。
4. 同一公司多个手机号只选择证据最高的一条。
5. 不同任务、不同轮次和应用重启后，相同手机号不会重复推送。
6. 同一公司获得更高质量号码时更新 ERP 原客户，不新建客户。
7. 单家公司搜索失败不阻塞持续任务。
8. 目标未达到时自动扩展候选和查询词，并持续运行。

## 测试范围

- 主体名称提取、别名归并和泛称拒绝
- A/B/C 级证据判定
- 正向搜索与手机号反向搜索闭环
- 多号码评分与最佳号码选择
- 跨任务、跨轮次和重启后的去重
- ERP 幂等更新与失败重试
- 豆包超时、限流、空结果和错误来源跳过
- 人工确认审计和人工推送
- 持续任务达到有效目标后自动停止
