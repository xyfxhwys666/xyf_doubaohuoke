# 数据来源与多模型核验设计

## 目标

任务创建页分别提供真实数据来源和核验模型的多选控件。用户可以决定是否调用高德，可零选、单选或多选 DeepSeek/豆包；所有正式线索必须保留可访问的来源链接。

## 数据来源

- `amap`：高德 POI 搜索，提供公司名、手机、地址和行业分类；仅保留手机、邮箱或微信至少一项有效的记录。
- `web_search`：公开网页搜索，按城市和关键词发现页面，并从页面正文提取公开手机、邮箱和明确标注的微信号。每个联系方式保留发现页面 URL。
- 至少选择一个真实数据来源。关闭高德时，公开网页搜索仍能独立运行。
- 全国城市清单仍可使用已配置的高德行政区接口生成；该调用只生成城市范围，不作为企业线索来源。

## 模型核验

- `deepseek` 和 `doubao` 是核验模型，不是数据来源。
- 模型只能阅读本次采集到的公司名、地址、服务说明、联系方式和来源 URL，判断是否符合任务需求；不得新增没有出现在证据中的联系方式。
- 单模型时标记为“单模型符合”或“单模型不符合”。
- 多模型结论一致时标记为“多模型一致符合”或“多模型一致不符合”；结论不一致时标记为“模型有分歧”。
- 模型接口失败不删除真实线索，记录核验失败并继续采集。

## 接口与存储

- `GET /api/v1/providers` 返回真实数据来源及配置状态。
- `GET /api/v1/models` 返回核验模型及配置状态。
- 创建任务增加 `models: string[]`，`providers` 继续保存真实来源。
- 线索增加 `verification_models` 和 `verification_detail`，下载及推送接口包含这些字段。

## 前端

- “真实数据来源”中分别显示公开网页搜索和高德地图复选框。
- “模型核验”中显示 DeepSeek 和豆包复选框；未配置项禁用并提示需要配置。
- 页面明确显示零模型、单模型或多模型核验模式。
- 结果表展示联系方式来源及模型核验结论。

## 错误处理与测试

- 未选择真实来源时，前后端都拒绝创建任务。
- 未配置的数据源或模型不能被选择。
- 使用模拟 HTTP 响应测试网页联系方式提取、模型 JSON 解析、单模型和多模型共识。
- 运行后端测试、代码检查、前端类型检查和生产构建，并通过浏览器验证页面渲染。
