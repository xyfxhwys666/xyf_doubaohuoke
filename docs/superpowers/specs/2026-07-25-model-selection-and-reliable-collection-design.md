# 模型选择与稳定采集设计

## 目标

用户只在自然语言中描述客户需求，并在输入框下方独立选择一个或多个已配置模型。采集继续以公开网页证据为准，通过串行任务调度、模型分批核验和候选网页复核提高稳定性与覆盖率，绝不直接保存模型编造的数据。

## 交互

- 输入框下展示豆包、DeepSeek、通义千问、Kimi、OpenAI、Claude、Gemini。
- 已配置模型可多选，未配置模型灰显并标注“未配置”。
- 至少选择一个模型；默认优先选择豆包，否则选择第一个已配置模型。
- 自然语言仅解析城市、客户类型、联系方式和数量，不再决定模型。

## 后端

- 自然语言创建任务接口接收明确的 `models` 数组，并校验均已配置。
- 所选模型共同生成搜索关键词并去重，随后分别核验公开网页候选。
- 每个模型按小批次核验，避免一次返回条目不完整。
- 同一进程只执行一个采集任务，其他任务等待，避免全国任务与临时任务同时触发搜索限制。
- 模型补充候选必须提供可访问来源 URL，且联系方式能在该网页正文中再次提取后才能入库。

## 真实性

- 手机、邮箱或微信必须来自可访问网页正文或搜索摘要。
- 模型只负责扩展关键词、提出候选和相关性核验，不能作为联系方式的唯一证据。
- 搜索失败仍记录异常，不用模拟数据掩盖失败。

## 验证

- API 测试覆盖显式模型覆盖自然语言、单模型和多模型。
- 模型测试覆盖分批核验与不完整响应。
- 服务测试覆盖任务互斥执行。
- 前端构建与页面模型灰显状态通过。
